# ADR-0003：应用启动时主动校验登录会话

## 状态

已废弃（2026-09-18）：启动校验被运行期统一 401 拦截器的静默刷新与重试链路取代。
本地令牌在启动时直接以已登录态渲染，令牌失效由首个业务请求的 401 触发静默续签并
自动重试一次；续签失败（含刷新令牌过期或被吊销）才清理会话并回到未登录态。
后端无需再实现 `GET /api/v1/auth/verify` 接口，本文其余内容仅作历史记录。

## 背景

访问令牌持久化在本地，应用启动时仅恢复令牌并视为已登录，令牌是否有效完全由
运行期间的第一个请求被动发现。用户往往在发送消息或保存表单时才收到
“登录状态已失效”，已输入的内容可能因此丢失。

## 决策

- 新增只读校验接口 `GET /api/v1/auth/verify`，携带 `Authorization: Bearer <token>`：
  有效返回 `204 No Content`，令牌过期、签名无效、已撤销或账号不可用返回 `401`，
  响应禁止缓存。服务端必须复用现有认证依赖校验令牌，不得只解析本地过期字段。
- 启动时存在本地令牌即进入校验中状态，校验成功前不挂载业务页面；
  无令牌直接进入未登录状态，不发起校验。
- 校验返回 401 时沿用统一响应拦截器的令牌拒绝机制清理会话；
  断网、超时、5xx 等其他失败保留令牌，由应用层展示可重试的错误页，不误判为过期。
- 校验请求禁用全局 HTTP 错误提示，由初始化边界统一呈现；运行期间的 401
  兜底保持不变。

## 影响

用户在进入页面时即可看到登录态结论，避免输入后失效。后端需实现上述接口；
接口未部署前，持有本地令牌的用户会看到“暂时无法验证登录状态”的错误页，
因此前后端需要协同发布。前端通过 Mock 验证了前端逻辑，尚未完成真实联调。
