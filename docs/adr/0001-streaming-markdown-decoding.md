# ADR-0001：在聊天协议边界增量解码流式正文

## 状态

已采纳。

## 背景

后端可用 JSON 信封返回 Markdown 正文与图表数据。流式传输尚未结束时，正文仍是
JSON 字符串片段，其中换行、引号和 Unicode 字符可能处于转义状态。若将该片段直接交给
Markdown 渲染器，标题和列表会因缺少真实换行而暂时显示为 Markdown 源语法，并在完整
响应经过 `JSON.parse` 后突然切换为正确格式。

## 决策

- 在聊天协议解析边界增量解码 JSON 字符串，渲染层只接收展示正文。
- 只发布边界完整的稳定解码前缀；末尾不完整转义等待后续分片补齐。
- 未转义引号表示正文结束，转义引号属于正文，后续图表字段不进入 Markdown 渲染。
- 完整响应仍由 `JSON.parse` 负责；最终非法信封继续按原文降级，避免静默丢失内容。

## 影响

流式标题和列表可在生成过程中直接按 Markdown 展示。协议适配逻辑增加了转义边界处理，
但消息领域类型、组件接口和后端协议均不需要变化。
