# Tazhive 前端编码规范

## 核心原则

- 代码首先服务于可读性、可维护性和可测试性，不为抽象而抽象。
- 一个文件只表达一个主要概念，一个模块只负责一个业务能力。
- 优先组合小组件和 Hook，避免页面组件同时处理数据、状态、布局和交互。
- 修改代码时同步清理失效类型、样式、导出和注释。

## 文件行数与拆分

源码、样式、配置和项目文档单文件最多 300 行，锁文件与工具生成文件除外。行数不由 Lint 阻断，但开发者和编码代理必须在交付前检查并主动拆分。

建议在 200–250 行开始评估。按以下顺序拆分：

1. 将独立视觉区域提取为子组件。
2. 将状态、副作用和事件编排提取为自定义 Hook。
3. 将类型、常量和静态数据移到专用文件。
4. 将可复用纯逻辑提取到 `lib`。
5. 将大块样式按组件边界拆为 SCSS Module。

禁止压缩代码、合并无关语句或制造超长行来规避限制。

## 命名规则

| 对象            | 规则               | 示例                |
| --------------- | ------------------ | ------------------- |
| React 组件      | PascalCase         | `UserProfile.tsx`   |
| Hook            | `use` + PascalCase | `useUserProfile.ts` |
| 函数、变量      | camelCase          | `loadUserProfile`   |
| 常量            | UPPER_SNAKE_CASE   | `DEFAULT_PAGE_SIZE` |
| 类型            | PascalCase         | `UserProfileProps`  |
| CSS Module 类名 | camelCase          | `actionButton`      |
| 业务目录        | kebab-case         | `resource-links`    |

名称必须描述意图，禁止长期使用 `data1`、`temp`、`handleThing`、`utils` 等模糊名称。

## 文件内部结构

文件内容按以下顺序组织：

1. 第三方依赖。
2. 当前模块内部相对依赖。
3. 使用 `@/` 的跨模块依赖。
4. Props 和局部类型。
5. 常量与静态配置。
6. 主要组件、Hook 或函数。

类型依赖使用 `import type`。优先具名导出，模块公共能力统一由根部 `index.ts` 再导出。默认导出只用于存在明确框架要求的入口。

## TypeScript

- 开启并保持严格类型检查，公共函数和 Hook 声明返回类型。
- Props 使用具名只读类型；集合优先使用 `readonly` 防止意外修改。
- 使用联合类型表达有限状态，不用多个布尔值组合隐含状态机。
- 禁止无理由使用 `any`、非空断言、双重断言或 `@ts-ignore`。
- 外部数据在边界处校验或转换，组件内部使用稳定的应用模型。
- 共享类型只在确实有多个模块消费时进入 `shared/types`，否则与业务代码就近存放。

## React 与 Hook

- 组件只负责渲染与明确的用户交互，数据获取和复杂副作用进入 Hook 或业务层。
- Hook 必须以 `use` 开头，遵守调用顺序并完整声明依赖。
- 不为简单派生值创建 State；优先在渲染期间计算，昂贵计算再考虑缓存。
- 不在 JSX 中编写多层三元表达式、大段数组转换或复杂匿名回调。
- 列表使用稳定业务标识作为 `key`，禁止在可变列表中使用数组索引。
- 事件函数描述业务行为，例如 `submitOrder`，避免只有实现细节的名称。
- React Compiler 已启用，不应无依据滥用 `useMemo` 和 `useCallback`。

## Props 与状态边界

- 业务数据、状态和回调只通过 Props 传给直接读取、转换或执行它们的组件。
- 自有组件不允许接收某个业务 Prop 后不使用、仅原样传给更深层后代；这种纯透传必须在合并前消除。
- 优先按职责重新组合组件或调整状态归属；确实存在跨层共享时，使用 feature/page 作用域 Context，并限制在最小有效子树。
- 不得仅为减少 Props 引入全局 Store、事件总线，或将带有业务含义的状态放入 `shared`。
- Context 应围绕单一业务能力设计，禁止形成混合页面布局、业务动作和无关状态的万能 Context。
- `children`、第三方组件插槽和协议适配参数可以由边界组件传递，但不得借此跨多个自有组件继续传递业务参数。
- 新增或修改组件 Props 时，代码评审必须检查接收组件是否为该参数的真实消费者。

## 样式

- 样式使用 Sass（SCSS 语法），由 Vite 内置支持编译，无需额外插件配置。
- 组件样式使用同目录 `*.module.scss`，禁止组件依赖其他模块的私有类名。
- 设计令牌、基础重置和全局元素样式统一位于 `src/app/styles`，入口 `index.scss` 用 `@use` 按令牌、重置、基础样式的顺序聚合，partial 文件使用 `_` 前缀。
- 颜色、字体、阴影和布局常量优先复用 CSS 变量；设计令牌必须是 CSS 自定义属性而非 SCSS 变量，否则无法支持运行时明暗主题切换。
- 类选择器保持扁平，嵌套限于伪元素、交互状态（`&:hover` 等）、媒体查询和同一组件内部的后代元素，避免依赖 DOM 层级和高特异性选择器。
- 响应式样式与组件样式放在同一 Module，断点保持项目统一。
- 交互状态必须覆盖 `hover`、`focus-visible` 和必要的禁用状态。

## 可访问性与界面状态

- 使用语义化 HTML；能用 `button`、`a`、`main`、`section` 时不模拟交互元素。
- 图片提供有效替代文本；纯装饰图片使用空 `alt` 或 `aria-hidden`。
- 新窗口链接添加安全的 `rel` 属性。
- 所有交互支持键盘访问，并提供可见焦点。
- 数据页面明确处理加载、空数据、失败和成功状态，错误信息应可理解且可恢复。

## 错误处理与注释

- 不静默吞掉异常；在合适边界转换错误并向用户提供可执行反馈。
- 日志不得包含令牌、密码、个人信息或完整敏感响应。
- 注释解释为什么需要特殊处理、兼容限制或设计取舍，不复述语句行为。
- TODO 必须包含明确后续动作，能立即处理的问题不留 TODO。

## 提交前检查

```bash
pnpm check
pnpm build
```

同时确认所有文件不超过 300 行、页面关键交互正常、控制台无错误、没有跨层深层导入和未使用资源。
